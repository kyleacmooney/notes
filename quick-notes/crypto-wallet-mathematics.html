Crypto Wallet Mathematics

Explains the mathematical foundations of cryptocurrency wallets, from elliptic curve cryptography to digital signatures

Asymmetric Cryptography Foundation

Crypto wallets are built on elliptic curve cryptography (ECC), specifically most use the secp256k1 curve (Bitcoin, Ethereum, etc.). The fundamental property is computational asymmetry: forward operations are fast, reverse operations are infeasible.

= Key Derivation Chain
$$\text{Private Key} \xrightarrow{\text{EC Multiply}} \text{Public Key} \xrightarrow{\text{Hash}} \text{Address}$$
Each arrow represents a one-way function that's easy to compute forward but infeasible to reverse.

1. Seed Phrase Generation

= Entropy Encoding
$$\text{128-256 bits entropy} \rightarrow \text{BIP-39 wordlist} \rightarrow \text{12-24 words}$$
Human-readable encoding of cryptographic randomness.
= Word Encoding
$$2048 = 2^{11} \implies \text{each word encodes 11 bits}$$
The wordlist size is chosen to make each word represent exactly 11 bits of entropy.

2. Hierarchical Deterministic Key Derivation

Your seed doesn't create just one key — it generates a hierarchical deterministic (HD) tree of keys using BIP-32/BIP-44 standards. This is why one seed phrase can recover unlimited addresses.

= Key Derivation Function
$$\text{Seed} \xrightarrow{\text{PBKDF2} + \text{HMAC-SHA512}} \text{Master Key} \rightarrow \begin{cases} \text{Account}_0 \rightarrow \text{Address}_{0,1,2,\ldots} \\ \text{Account}_1 \rightarrow \text{Address}_{0,1,2,\ldots} \\ \vdots \end{cases}$$
All addresses are mathematically derived from a single master key.

3. The Elliptic Curve

:= secp256k1 Curve
$$y^2 = x^3 + 7 \pmod{p}$$
The specific elliptic curve used by Bitcoin and Ethereum.
= Prime Modulus
$$p = 2^{256} - 2^{32} - 977$$
A massive prime number (~2²⁵⁶) defining the finite field.
= Public Key Generation
$$K_{\text{pub}} = k \times G$$
Multiply generator point G by private key k using elliptic curve point addition.
✎ One-Way Property
$$\text{Given } K_{\text{pub}} \text{ and } G, \text{ finding } k \text{ is the Elliptic Curve Discrete Log Problem}$$
No efficient algorithm exists to reverse this multiplication.

4. Digital Signatures (ECDSA)

When you send crypto, you create a digital signature proving you own the private key without revealing it.

→ Step 1: Hash Transaction
$$h = \text{SHA256}(\text{"Send 1 ETH from 0xABC to 0xDEF"})$$
Create a fixed-size digest of the transaction data.
→ Step 2: Sign
$$(r, s) = \text{ECDSA}_{\text{sign}}(h, k_{\text{private}})$$
Produce a ~64 byte signature using your private key.
→ Step 3: Verify
$$\text{ECDSA}_{\text{verify}}(h, (r,s), K_{\text{pub}}) \stackrel{?}{=} \text{valid}$$
Anyone can verify using only your public key.

5. Security Analysis

= Key Space Size
$$2^{256} \approx 10^{77} \approx \text{atoms in observable universe}$$
Brute-force guessing is physically impossible.
★ ECDLP Hardness
$$\nexists \text{ efficient algorithm: } K_{\text{pub}} \mapsto k$$
The security assumption underlying all elliptic curve cryptography.

6. Quantum Computing Threat

✎ Shor's Algorithm
$$\text{Quantum: } O((\log n)^3) \text{ vs Classical: } O(e^{n^{1/3}})$$
A sufficiently large quantum computer could break ECDSA, driving research into post-quantum signatures.
